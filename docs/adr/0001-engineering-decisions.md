# Engineering decision record

Accepted for Phase 5 on 2026-10-17; implementation remains in an unmerged stack. These decisions are proportionate to the current requirements, not universal prescriptions.

| Decision                 | Chosen implementation                                                                                                                                          | Alternatives and tradeoff                                                                                                                                                             |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| npm monorepo             | Frontend/backend workspaces, one frozen lockfile, shared strict TS                                                                                             | Separate repos add coordination; a monorepo task framework adds no present value                                                                                                      |
| REST API proxy           | Browser calls our relative API; backend fixes GitHub host, validates/maps data                                                                                 | Browser-direct GitHub spreads contracts/rate errors and complicates future origin policy                                                                                              |
| No database/auth         | Stateless public-data explorer                                                                                                                                 | Accounts/persistence would require a new product story, threat model and operational cost review                                                                                      |
| Process-local cache      | 100 successful URL-keyed entries, TTL60s/FIFO                                                                                                                  | Redis/distributed cache adds infrastructure; this cache cannot coordinate replicas/concurrent misses or guarantee quotas                                                              |
| Simple routing           | Native History API for search/detail, preserve mounted hidden search                                                                                           | A router library becomes useful for deeper route trees; full-refresh state is intentionally not persisted                                                                             |
| Single-origin production | Express serves same-build React and API with explicit SPA fallback                                                                                             | Separate origins require CORS, extra routing and release coordination; Vite remains dev-only                                                                                          |
| HTTP hardening           | Small tested boundary for CSP/headers/limits/redacted logs and readiness/runtime helper                                                                        | An established middleware library can be appropriate later; current surface has no uploads, cookies or sessions, and no arbitrary body parsing                                        |
| Docker                   | Official Node24 LTS Bookworm slim, multi-stage builds, backend-only prod dependencies, UID1000/read-only Compose                                               | Distroless could reduce tools further but complicates debugging/health; Alpine changes libc/native tooling. Docker is reproducibility evidence, not a required future hosting product |
| Version pinning          | Node24 official index pinned to `sha256:a5f4366e834695d5f363b920c104953a535d3a9864d1bdf74566a0ebe01daee5`; actions pinned to resolved v5 SHAs; lockfile frozen | Floating tags silently change; permanent pins without refresh miss fixes. Re-resolve/review/rebuild periodically; tested amd64 image reports Node24.22.0, cloud/CI Node24.19.0        |
| CI/CD boundary           | Public standard Ubuntu quality + local Docker build/smoke jobs, no publish/deploy step                                                                         | Premium runners, registry publication or deployment are unnecessary/unauthorized. This is CI and delivery readiness, not automatic deployment                                         |
| Coverage                 | V8 measured boundary tests, thresholds 90% lines/statements and 85% branches/functions                                                                         | 100% global threshold encourages shallow tests; entry modules verified through actual startup/browser/container checks instead of inflating unit counts                               |
| Hosting                  | Deferred pending current no-card/no-overage terms and explicit Phase 6 review                                                                                  | No provider activated or called verified-free from stale marketing. Runtime can use a compatible free non-container host if terms/support actually satisfy requirements               |
| Observability            | Structured redacted stdout, generated UUID correlation, health/readiness, Docker healthcheck                                                                   | No paid tracing/monitoring agent; logs exclude IPs, query/path identifiers, request bodies, credentials and error objects                                                             |
| Progress evidence        | Permanent PHASE_PROGRESS journal plus per-phase verification/lesson, metadata versus test provenance                                                           | Chat-only summaries cannot be reliably audited from GitHub; final commit SHA is reported separately to avoid circular self-reference                                                  |

Consequences: service replicas do not share state; public API quotas and hosting sleep/limits may affect availability; native assistive/performance and image OS vulnerability scans remain separate evidence. Read the deployment checklist before interpreting this as a release approval.
